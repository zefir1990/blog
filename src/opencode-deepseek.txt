Title: Установка OpenCode и подключение DeepSeek
Slug: opencode-deepseek
Categories: notes
OpenCode — это открытый агент для программирования, который живёт прямо в терминале. Он умеет читать файлы проекта, править код, запускать команды и тесты, искать по репозиторию и работать с git — примерно то же, что делают Claude Code и другие консольные агенты. Главное отличие в том, что OpenCode не привязан к одному поставщику моделей: через него можно подключить десятки провайдеров, в том числе DeepSeek. В этой заметке я опишу установку агента и подключение к нему DeepSeek.

<h2>Что понадобится</h2>

Для работы нужны всего две вещи:

<ul>
<li><b>Современный терминал.</b> Подойдёт WezTerm, Alacritty, Ghostty, Kitty или любой другой.</li>
<li><b>API-ключ провайдера.</b> В нашем случае — DeepSeek.</li>
</ul>

Node.js не обязателен, если ставить агент штатным установочным скриптом, — binary приезжает готовым.

<h2>Установка</h2>

Самый простой способ — официальный установочный скрипт:

<pre><code>
curl -fsSL https://opencode.ai/install | bash
</code></pre>

Он сам определит платформу и положит исполняемый файл в PATH. После установки стоит проверить, что всё на месте:

<pre><code>
opencode --version
</code></pre>

Если команда отображает версию, установка прошла успешно.

<h2>Установка другими способами</h2>

Если вы предпочитаете пакетные менеджеры, вариантов несколько. Через Node.js:

<pre><code>
npm install -g opencode-ai
</code></pre>

То же самое умеют Bun, pnpm и Yarn:

<pre><code>
bun install -g opencode-ai
pnpm install -g opencode-ai
yarn global add opencode-ai
</code></pre>

В macOS и Linux есть Homebrew. Обратите внимание: рекомендуют именно tap от разработчиков, а не официальную формулу — она обновляется реже:

<pre><code>
brew install anomalyco/tap/opencode
</code></pre>

В Arch Linux:

<pre><code>
sudo pacman -S opencode
paru -S opencode-bin
</code></pre>

Первая команда ставит стабильную версию из репозитория, вторая — свежую из AUR.

<h2>Установка в Windows</h2>

В Windows рекомендуют работать через WSL: так и производительность выше, и совместимость с возможностями агента полная. Но есть и нативные способы. Через Chocolatey, Scoop или npm:

<pre><code>
choco install opencode
scoop install opencode
npm install -g opencode-ai
</code></pre>

Есть и вариант через Mise, а также контейнер Docker:

<pre><code>
mise use -g github:anomalyco/opencode
docker run -it --rm ghcr.io/anomalyco/opencode
</code></pre>

Наконец, готовый бинарник всегда можно взять со страницы релизов на GitHub.

<h2>Ключ DeepSeek</h2>

Ключ создаётся в личном кабинете DeepSeek. Заходим на platform.deepseek.com, открываем раздел с API-ключами и нажимаем создание нового ключа. Полученную строку лучше сразу сохранить: показана она будет только один раз.

<h2>Подключение DeepSeek</h2>

Дальше всё делается внутри самого агента. Запускаем OpenCode в терминале:

<pre><code>
opencode
</code></pre>

В интерфейсе выполняем команду подключения:

<pre><code>
/connect
</code></pre>

В открывшемся списке провайдеров ищем <b>DeepSeek</b>, выбираем его и вставляем API-ключ. Ключи, добавленные таким образом, сохраняются в файл:

<pre><code>
~/.local/share/opencode/auth.json
</code></pre>

После подключения остаётся выбрать модель командой:

<pre><code>
/models
</code></pre>

В списке будут доступны модели DeepSeek, в том числе <b>deepseek-v4-pro</b>, <b>deepseek-flash</b> и <b>deepseek-v4-flash</b>. Для рутинной работы в репозитории вполне хватает flash-варианта; на сложные задачи имеет смысл переключаться на pro.

<h2>Настройка через конфиг</h2>

Если не хочется хранить ключ через мастер или нужно задать свой адрес API, провайдер описывается прямо в конфигурационном файле <b>opencode.json</b>:

<pre><code>
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepseek": {
      "options": {
        "baseURL": "https://api.deepseek.com"
      }
    }
  }
}
</code></pre>

Поле <b>baseURL</b> пригодится, если вы ходите через прокси или собственный шлюз. Сам ключ в этом случае удобно передать переменной окружения:

<pre><code>
export DEEPSEEK_API_KEY=ваш_ключ_deepseek
opencode
</code></pre>

Такой вариант хорош для CI и одноразовых запусков: ключ не оседает в хранилище, а живёт только в окружении процесса.

<h2>Первый запуск в проекте</h2>

Переходим в каталог проекта и запускаем агента:

<pre><code>
cd ваш_проект
opencode
</code></pre>

Первым делом полезно инициализировать его:

<pre><code>
/init
</code></pre>

OpenCode проанализирует структуру проекта и создаст файл <b>AGENTS.md</b> — аналог инструкций для агента. Этот файл стоит закоммитить в git: он помогает агенту понимать принятые в проекте соглашения и паттерны.

<h2>Как этим пользоваться</h2>

Работа строится примерно так же, как с другими агентами. Пара приёмов, которые стоит знать сразу:

<ul>
<li><b>Режим планирования.</b> Клавиша <b>Tab</b> переключает агента между режимами планирования и сборки. В первом он только предлагает, как решить задачу, и ничего не меняет, — удобно проверить замысел до правок.</li>
<li><b>Ссылки на файлы.</b> Клавиша <b>@</b> открывает нечёткий поиск по файлам проекта, чтобы передать агенту конкретный файл в контекст.</li>
<li><b>Откат изменений.</b> Команда <b>/undo</b> отменяет последние правки и возвращает исходный запрос, <b>/redo</b> — возвращает их обратно. Откатывать можно несколько шагов подряд.</li>
<li><b>Обмен диалогом.</b> Команда <b>/share</b> создаёт ссылку на текущую беседу и копирует её в буфер обмена. По умолчанию диалоги никуда не публикуются.</li>
</ul>

Для простых изменений можно и не переходить в режим планирования, а сразу описать, что нужно сделать, и указать файлы через @.

<h2>На что обратить внимание</h2>

Пара практических моментов. OpenCode не требует подписки: вы платите провайдеру напрямую по факту расхода токенов, поэтому длинные сессии с DeepSeek предсказуемо дешевле топовых моделей. Ключ хранится локально в auth.json — это стоит учитывать на общей машине, а для чужих окружений надёжнее переменная окружения.

И ещё: качество ответа на сложных архитектурных задачах у моделей разных классов отличается, поэтому для проектирования имеет смысл брать модель посильнее, а рутину отдавать быстрой и дешёвой.
